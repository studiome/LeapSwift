# Mock Mode

Develop and demo hand tracking without the Ultraleap service or a device.

## Overview

``LeapController`` normally requires the Ultraleap Hand Tracking service and a
connected device. LeapSwift can substitute synthetic hand data instead, using
the exact same ``LeapController/events`` stream, so nothing about the code
that consumes it changes.

Mocking is always opt-in. `LeapController()` with no `mock` argument talks to
real LeapC exactly as it did before mocking existed — a release build can
never start streaming fake frames unless something explicitly asks for it.

## Choosing a Policy

``MockPolicy`` has three cases:

- ``MockPolicy/disabled`` — real LeapC only. The default.
- ``MockPolicy/always`` — mock only. LeapC is never touched, so this works
  with no Ultraleap installation at all.
- ``MockPolicy/whenNoDevice`` — tries the real device first. Falls back to the
  mock if the connection can't be made, no device is found, or a device stops
  producing frames — and switches back automatically once a real device
  starts working.

```swift
let controller = try await LeapController(mock: .always)
```

### Resolving From the Environment

Passing `mock` explicitly hardcodes it in source. ``MockPolicy/resolved(environment:arguments:default:)``
reads it from outside the process instead, which is usually more useful — it's
what `LeapController`'s `mock` parameter defaults to:

```swift
public init(
    trackingMode: TrackingMode = .desktop,
    mock: MockPolicy = .resolved(),
    mockScenario: MockScenario = .idleRightHand
) async throws
```

It checks, in order: the `-LeapSwiftMock` launch argument (settable per Xcode
scheme, without touching source), then the `LEAPSWIFT_MOCK` environment
variable, then ``MockPolicy/disabled`` if neither is set. Both accept the same
values:

| Value | Policy |
| ----- | ------ |
| `off`, `disabled`, `0` | ``MockPolicy/disabled`` |
| `auto`, `whenNoDevice` | ``MockPolicy/whenNoDevice`` |
| `always`, `on`, `1` | ``MockPolicy/always`` |

## Scenarios

``MockScenario`` selects what the mock streams. Every scenario is periodic, so
it loops seamlessly:

- ``MockScenario/noHands`` — nothing in view.
- ``MockScenario/idleRightHand`` — one relaxed hand, gently swaying.
- ``MockScenario/bothHandsIdle`` — both hands, relaxed.
- ``MockScenario/openClose`` — a hand cycling between open and a fist.
- ``MockScenario/pinch`` — a hand cycling through a thumb-to-index pinch.
- ``MockScenario/wave`` — a hand waving side to side.

```swift
let controller = try await LeapController(mock: .always, mockScenario: .pinch)
```

## Behavior While Mocked

Every ``LeapController`` method works the same whether mocked or not, but a
few have different results because there is no real connection underneath:

- ``LeapController/deviceInfo()`` returns a pseudo ``DeviceInfo`` rather than
  `nil`.
- ``LeapController/version(of:)`` returns a fixed, obviously-synthetic version
  rather than a real one.
- ``LeapController/setTrackingMode(_:)`` records the mode but has nothing to
  apply it to.
- ``LeapController/setBackgroundFrames(enabled:)`` always succeeds — there is
  no app-focus concept for synthetic frames.

## Driving the Mock Directly

``LeapController`` is the usual entry point, but the pieces underneath it are
public too, for a preview, a SwiftUI canvas, or a test that wants finer
control than a policy gives you.

``MockLeapServer`` is the actor that actually generates the event stream:

```swift
let server = MockLeapServer(scenario: .idleRightHand)
await server.start()
for await event in server.events {
    // .connected, then .deviceFound, then a trackingFrame every frame.
}
```

Inject a specific frame or event outside the running scenario:

```swift
await server.inject(myCustomFrame)
await server.inject(.deviceLost)
```

Or build frames yourself with ``MockHandFactory``, the pure function layer
`MockLeapServer` is built on:

```swift
let frame = MockHandFactory.frame(scenario: .pinch, frameId: 0, time: 0.5)
let hand = MockHandFactory.hand(type: .right, id: 1, pose: myPose)
```

## Recording and Replaying Sessions

``MockRecording`` reads and writes a scenario as JSON. LeapSwift ships one
recording per scenario, generated by ``MockRecording/generate(scenario:duration:frameRate:)``:

```swift
let recording = try MockRecording.bundled(.wave)
await server.play(recording, loop: true)
```

The same file format works for a session you capture or hand-author yourself.
To capture one, collect frames off a real controller and write them out:

```swift
var captured: [HandFrame] = []
for await frame in realController.frames {
    guard let frame else { continue }
    captured.append(frame)
    if captured.count == 300 { break }
}
try MockRecording(name: "my-gesture", frameRate: 30, frames: captured).write(to: myURL)
```

Replay it later through the same `play(_:loop:)` call:

```swift
let loaded = try MockRecording.load(contentsOf: myURL)
await server.play(loaded)
```
